# Практическая работа № 2. Вариант 27

## Этап 2. Сбор данных

Приложение получает все прямые зависимости указанной версии пакета
Rust (Cargo) по URL репозитория и выводит их на экран.
Используется только стандартная библиотека Python 3.9 или новее:
`urllib.request` для HTTP и `json` для разбора данных.
Cargo, другие менеджеры пакетов и сторонние библиотеки получения
зависимостей не используются. Установка зависимостей и сборка не нужны.

## Запуск и тесты

Команды выполняются из корня проекта. Для обращения к реальному
репозиторию требуется доступ к сети.

Windows:

```bat
run.bat config.json
py -3 src/main.py config.json
py -3 -m unittest discover -s tests -v
```

Linux/macOS:

```sh
sh run.sh config.json
python3 src/main.py config.json
python3 -m unittest discover -s tests -v
```

Для выбора интерпретатора в скриптах используется переменная `PYTHON_EXE`.
Справка: `python3 src/main.py --help` (Windows: `py -3` вместо `python3`).
Тесты не требуют доступа к внешней сети: HTTP-проверки запускают локальный
сервер с данными формата индекса Cargo.

## Настройки

Единственный позиционный аргумент — путь к JSON-конфигурации в UTF-8.
Относительный путь к конфигурации отсчитывается от рабочего каталога.
Пять параметров этапа 1 сохраняются:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `package` | строка | Имя анализируемого пакета |
| `repository` | строка | Базовый HTTP(S)-адрес sparse-индекса Cargo |
| `test_mode` | логическое | На этапе 2 указывается `false` |
| `version` | строка | Точная версия анализируемого пакета |
| `output` | строка | Имя будущего изображения SVG |

```json
{
  "package": "serde",
  "repository": "https://index.crates.io",
  "test_mode": false,
  "version": "1.0.210",
  "output": "dependencies.svg"
}
```

`repository` — HTTP(S)-адрес корня индекса, без префикса `sparse+`.
Это не URL страницы пакета на crates.io и не адрес Git-репозитория.
`version` задается в формате SemVer, без диапазона версий и префикса `v`.
Имя пакета начинается с буквы ASCII, далее разрешены буквы ASCII,
цифры, дефис и подчеркивание.
Все строковые параметры непустые, без управляющих символов
и пробелов по краям. Неизвестные параметры отклоняются.
Для `output` требуется расширение `.svg` и существующий каталог;
относительный путь отсчитывается от каталога JSON-конфигурации.
Изображение на этапе 2 не создается.
Параметр `test_mode` сохранен из этапа 1, но работа с тестовым графом
относится к этапу 3. При `true` выводится явное сообщение об этом.

## Получение и вывод зависимостей

По имени пакета вычисляется путь в индексе Cargo, выполняется один
HTTP-запрос и в построчном JSON выбирается запись с указанной версией.
Затем из поля `deps` извлекаются все прямые зависимости.

После заголовка с именем и версией каждая зависимость выводится отдельной
JSON-строкой с полями из индекса. В частности:

- `name` — имя зависимости или ее псевдоним;
- `package` — исходное имя переименованного пакета, если задано;
- `req` — требование к версии зависимости;
- `kind` — категория: `normal`, `build` или `dev`;
- `optional` — признак необязательной зависимости;
- `target` — условие целевой платформы.

Выводятся все записи, включая необязательные и платформенные зависимости,
а также зависимости для сборки и тестирования. Переименования сохраняются.
Требование `req` не подменяется конкретной разрешенной версией.
Для пакета без зависимостей выводится `Прямых зависимостей нет.`.
Вывод пяти настроек был требованием только этапа 1 и здесь отсутствует.
Граф транзитивных зависимостей на этапе 2 не строится.

Формат источника данных:
[официальная документация индекса Cargo](https://doc.rust-lang.org/cargo/reference/registry-index.html).

## Ошибки

При успехе код завершения — 0. При ошибке — 2, сообщение выводится
в stderr, частичный результат и traceback не выводятся.
Обрабатываются ошибки конфигурации, отсутствующий пакет (HTTP 404),
другие ошибки HTTP, сетевые ошибки, тайм-аут, неверная кодировка,
поврежденный JSON индекса, несовпадение имени, отсутствие указанной версии
и некорректный список зависимостей. Тайм-аут HTTP-запроса — 20 секунд.

## Функции

`src/main.py`: `main()` читает настройки, получает и выводит зависимости.

`src/config.py`:

- `read_json(path)` — чтение объекта JSON;
- `check_field(name, value)` — проверка типа и базовых ограничений поля;
- `check_fields(data)` — проверка состава конфигурации;
- `local_path(value, base)` — вычисление пути относительно конфигурации;
- `check_repository(data, base)` — проверка URL или тестового файла;
- `check_output(value, base)` — проверка имени будущего SVG;
- `check_version(value)` — проверка SemVer;
- `load_config(filename)` — загрузка и общая проверка настроек.

`src/registry.py`:

- `index_path(package)` — вычисление пути в индексе Cargo;
- `download_index(repository, package)` — загрузка индекса одного пакета;
- `select_version(text, package, version)` — выбор указанной версии;
- `validate_dependencies(entry)` — проверка списка прямых зависимостей;
- `get_dependencies(config)` — получение зависимостей по конфигурации.

`ConfigError` представляет ошибку настроек, `RegistryError` — ошибку
сбора данных. Тесты проверяют настройки, правила путей, точный выбор версии,
категории зависимостей, пустой результат, HTTP, ошибки данных и вывод CLI.
