# Практическая работа № 2. Вариант 27

## Этап 1. Минимальный прототип с конфигурацией

CLI-приложение на Python для чтения настроек будущего инструмента
визуализации зависимостей пакетов Rust (Cargo).
Реализован только этап 1: чтение JSON, проверка всех пяти параметров
и вывод в формате `ключ=значение`.
На этом этапе зависимости не загружаются, граф и изображение не создаются.
Используется стандартная библиотека Python 3.9 или новее.
Установка зависимостей и сборка не требуются.

## Запуск

Команды выполняются из корня проекта.

Windows:

```bat
run.bat config.json
py -3 src/main.py config.json
py -3 -m unittest discover -s tests -v
```

Linux/macOS:

```sh
sh run.sh config.json
python3 src/main.py config.json
python3 -m unittest discover -s tests -v
```

При необходимости путь к интерпретатору задается переменной `PYTHON_EXE`.
Для справки: `py -3 src/main.py --help` (Windows) или
`python3 src/main.py --help` (Linux/macOS).
Единственный позиционный аргумент приложения — путь к JSON-конфигурации.
Относительный путь к конфигурации отсчитывается от рабочего каталога.

## Настройки

Файл `config.json` имеет кодировку UTF-8 и содержит пять обязательных полей.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `package` | строка | Имя анализируемого пакета |
| `repository` | строка | URL репозитория или путь тестового файла |
| `test_mode` | логическое | `true` для тестового репозитория |
| `version` | строка | Версия пакета |
| `output` | строка | Имя будущего файла изображения |

```json
{
  "package": "serde",
  "repository": "https://index.crates.io",
  "test_mode": false,
  "version": "1.0.210",
  "output": "dependencies.svg"
}
```

Пример вывода:

```text
package=serde
repository=https://index.crates.io
test_mode=false
version=1.0.210
output=dependencies.svg
```

При `test_mode=false` проверяется синтаксис URL HTTP(S).
Доступность сети, наличие пакета и его версии на этапе 1 не проверяются.
При `test_mode=true` проверяется наличие файла тестового репозитория.
Его содержимое на этапе 1 не анализируется.
Пути `repository` в тестовом режиме и `output` отсчитываются от каталога JSON.

## Проверки и обработка ошибок

При ошибке приложение выводит сообщение в stderr и возвращает код 2.
При успехе код завершения — 0. Частичный результат при ошибке не выводится.
Отсутствие файла, недопустимая кодировка UTF-8, поврежденный JSON,
отсутствующие поля, неверные типы и неизвестные поля обрабатываются.
Строковые поля не должны быть пустыми, содержать управляющие символы
или пробелы по краям.

Следующие правила проверки значений приняты для реализации этапа:

| Поле | Проверка | Пример ошибочного значения |
| --- | --- | --- |
| `package` | Буква ASCII в начале, далее буквы, цифры, `_`, `-` | `bad name` |
| `repository` | URL HTTP(S) либо существующий тестовый файл | `not-a-url` |
| `test_mode` | Только JSON `true` или `false` | `"false"` |
| `version` | Формат SemVer, например `1.2.3` | `1.0` |
| `output` | Расширение `.svg`, допустимое имя, существующий каталог | `graph.png` |

SVG соответствует формату изображения из этапа 5 варианта 27.
Проверка возможности записи файла будет актуальна при создании изображения;
на этапе 1 файл не создается.

Для ручной демонстрации измените одно значение в копии `config.json`
на пример из последнего столбца и запустите приложение с этой копией.
Например, при `"version": "1.0"` будет выведено:

```text
Ошибка: version: ожидается версия вида 1.2.3.
```

Автоматическая демонстрация ошибок всех пяти параметров:

```sh
python3 -m unittest discover -s tests -v
```

В Windows замените `python3` на `py -3`.
Тесты проверяют корректную конфигурацию, отсутствие каждого поля,
неверные значения всех пяти параметров, тестовый путь, ошибки файла,
вывод приложения и его коды завершения.

## Функции

`src/main.py`:

- `main()` — аргументы командной строки, вывод параметров и ошибок.

`src/config.py`:

- `read_json(path)` — чтение объекта JSON из файла.
- `check_field(name, value)` — проверка типа и базовых ограничений поля.
- `check_fields(data)` — проверка обязательных полей и их типов.
- `local_path(value, base)` — вычисление пути относительно конфигурации.
- `check_repository(data, base)` — проверка URL или тестового файла.
- `check_output(value, base)` — проверка имени будущего изображения.
- `check_version(value)` — проверка версии SemVer.
- `load_config(filename)` — загрузка и общая проверка настроек.

`ConfigError` представляет ошибку конфигурации.
`tests/test_config.py` содержит тесты на основе `unittest`.
