# Практическая работа № 2. Вариант 27

## Этап 5. Визуализация

Программа формирует текстовое представление графа зависимостей
на языке PlantUML и сохраняет изображение в формате SVG.
Представлены визуализации для трех различных тестовых пакетов: A, B, C.
Результаты сравнены с выводом штатного инструмента Cargo — `cargo tree`.

Граф строится собственным кодом с помощью DFS без рекурсии.
Получение зависимостей менеджером пакетов или сторонней библиотекой
в приложении не используется. Cargo запускается отдельно для сравнения.

## Подготовка и запуск

Требуются Python 3.9+, Java и PlantUML JAR.
Проверено с Java 21 и PlantUML 1.2026.2.
Установка Python-библиотек и сборка приложения не требуются.

Скачайте `plantuml.jar` со страницы
[PlantUML](https://github.com/plantuml/plantuml/releases).
Укажите путь к нему в `PLANTUML_JAR` или поместите в `tools/plantuml.jar`.
Файл JAR не добавляется в репозиторий.
Рендеринг выполняется локально; используется встроенная в PlantUML
Smetana, установка Graphviz не требуется.

PowerShell, команды из корня проекта:

```powershell
$env:PLANTUML_JAR = 'C:\tools\plantuml.jar'
.\run.bat examples\A-config.json
.\run.bat examples\B-config.json
.\run.bat examples\C-config.json
```

Linux/macOS:

```sh
export PLANTUML_JAR=/path/to/plantuml.jar
sh run.sh examples/A-config.json
sh run.sh examples/B-config.json
sh run.sh examples/C-config.json
```

`java` должен быть доступен в PATH. При необходимости путь к Java
задается в `JAVA_EXE`, а интерпретатор скриптов запуска — в `PYTHON_EXE`.
Прямой запуск: `py -3 src/main.py config.json` или
`python3 src/main.py config.json`.
Справка: `py -3 src/main.py --help`.

## Конфигурация

Единственный аргумент CLI — путь к JSON-конфигурации UTF-8.
Относительный путь к ней отсчитывается от рабочего каталога.

| Параметр | Тип | Назначение |
| --- | --- | --- |
| `package` | строка | Имя корневого пакета |
| `repository` | строка | URL индекса или путь к файлу тестового репозитория |
| `test_mode` | логическое | `true` для тестового репозитория |
| `version` | строка | Версия Cargo-пакета |
| `output` | строка | Путь к сохраняемому SVG |

Пример `examples/A-config.json`:

```json
{
  "package": "A",
  "repository": "repository.json",
  "test_mode": true,
  "version": "1.0.0",
  "output": "../demonstration/A.svg"
}
```

Пути тестового репозитория и выходного файла отсчитываются от каталога
конфигурации. Родительский каталог выходного файла должен существовать.
Рядом с SVG сохраняется сформированное описание с расширением `.puml`.

Все параметры обязательны, неизвестные поля отклоняются.
Строки непустые, без управляющих символов и пробелов по краям.
`test_mode` принимает только JSON `true` или `false`.
Версия проверяется как SemVer; в тестовом графе версии не используются.
`output` должен иметь расширение `.svg`.
Имена тестовых пакетов содержат только большие латинские буквы.

Сохранен HTTP-режим предыдущих этапов: при `test_mode=false` параметр
`repository` задает HTTP(S)-корень sparse-индекса Cargo, без `sparse+`.
Имя Cargo-пакета начинается с буквы ASCII, далее разрешены буквы ASCII,
цифры, дефисы и подчеркивания. Версия корня выбирается точно,
версии зависимостей — по требованиям `req`.
Режим обратного вывода относился только к этапу 4;
`reverse_package` на этапе 5 не принимается.

## Три примера визуализации

Файл `examples/repository.json`:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}
```

| Корневой пакет | Конфигурация | SVG | Зависимости |
| --- | --- | --- | --- |
| A | `examples/A-config.json` | `demonstration/A.svg` | A → B, C; B → D; C → D |
| B | `examples/B-config.json` | `demonstration/B.svg` | B → D |
| C | `examples/C-config.json` | `demonstration/C.svg` | C → D |

Изображение содержит только достижимые из выбранного корня пакеты.
Общая зависимость D изображается одной вершиной.
Готовые SVG и PUML предоставлены отдельным архивом.

## Сравнение с Cargo

Для независимого сравнения тот же набор пакетов оформлен как локальные
Cargo-проекты в `examples/cargo-comparison`. Зависимости в Cargo.toml
указаны через `path`. Загрузка внешних пакетов для сравнения не требуется.
Приложение читает JSON-репозиторий, а Cargo — собственные Cargo.toml.

```sh
cargo tree --manifest-path examples/cargo-comparison/Cargo.toml -p A --offline --prefix depth --format "{p}"
cargo tree --manifest-path examples/cargo-comparison/Cargo.toml -p B --offline --prefix depth --format "{p}"
cargo tree --manifest-path examples/cargo-comparison/Cargo.toml -p C --offline --prefix depth --format "{p}"
```

## Тесты

Windows:

```powershell
py -3 -m unittest discover -s tests -v
```

Linux/macOS:

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют настройки, построение графа, циклы, версии, текст PlantUML,
сохранение файлов и ошибки. В тестах внешний рендерер подменяется;
установка Java и PlantUML для тестов не нужна.
Реальная генерация SVG дополнительно проверена для пакетов A, B, C.

## Ошибки и ограничения

При успехе код завершения — 0, при ошибке — 2.
Сообщение выводится в stderr без traceback.
Обрабатываются ошибки JSON, параметров, файлов, сети, индекса и версий.
Для визуализации обрабатываются отсутствие JAR, ошибка запуска Java,
тайм-аут, ошибка PlantUML, неверный SVG и ошибка записи.
Тайм-аут HTTP — 20 секунд, рендеринга — 60 секунд.

В HTTP-режиме граф включает объявленные зависимости всех категорий.
Features и платформа не выбираются; глобальное согласование Cargo.lock
не выполняется. Зависимости другого индекса явно отклоняются.

## Структура проекта

- `src` — исходный код приложения;
- `tests` — тесты, включая сохраненные проверки предыдущих этапов;
- `examples` — конфигурации и тестовые репозитории;
- `examples/cargo-comparison` — локальные Cargo-пакеты для сравнения;
- `demonstration` — текстовые результаты;
- `run.bat`, `run.sh` — скрипты запуска;
- `config.json` — конфигурация визуализации пакета A;
- `.gitignore` — исключения служебных файлов и сгенерированных изображений.

## Функции

`src/cargo.py`:

- `parse_index()` — Прочитать и проверить записи версий одного пакета.
- `dependency_name()` — Получить реальное имя пакета с учетом переименования.
- `check_registry()` — Проверить, что зависимость принадлежит выбранному индексу.
- `__init__()` — Запомнить URL индекса и создать кеш на время одного запуска.
- `records()` — Получить все версии пакета с кешированием HTTP-ответа.
- `entry()` — Найти точную версию узла в индексе пакета.
- `resolve()` — Выбрать максимальную неотозванную подходящую версию ребра.
- `children()` — Получить узлы всех прямых зависимостей конкретной версии.

`src/config.py`:

- `read_json()` — Прочитать объект JSON из файла UTF-8.
- `check_field()` — Проверить тип и базовые ограничения одного параметра.
- `check_fields()` — Проверить наличие и типы пяти параметров.
- `local_path()` — Определить путь относительно каталога конфигурации.
- `check_repository()` — Проверить URL или наличие файла тестового репозитория.
- `check_output()` — Проверить имя будущего изображения, не создавая файл.
- `check_version()` — Проверить формат версии пакета Cargo (SemVer).
- `load_config()` — Загрузить и проверить все параметры без обращения к сети.

`src/graph.py`:

- `build_graph()` — Построить достижимый граф DFS со стеком, сохраняя ребра циклов.
- `validate_test_graph()` — Проверить имена пакетов и ссылки в тестовом репозитории.
- `read_test_repository()` — Прочитать и проверить весь тестовый репозиторий.
- `load_test_graph()` — Построить достижимый граф тестового репозитория.

`src/main.py`:

- `node_label()` — Вернуть имя тестового узла или имя и версию Cargo-пакета.
- `get_graph()` — Выбрать источник и область поиска для текущего режима.
- `format_result()` — Подготовить текстовый список смежности визуализируемого графа.
- `main()` — Вывести результат выбранного режима или сообщение об ошибке.

`src/registry.py`:

- `index_path()` — Сформировать путь к файлу пакета по правилам индекса Cargo.
- `download_index()` — Загрузить индекс одного пакета по HTTP без вызова Cargo.
- `validate_dependencies()` — Проверить прямые зависимости без исключения отдельных категорий.

`src/reverse.py`:

- `reverse_dependencies()` — Найти все пакеты, зависящие от target прямо или транзитивно.
- `find_target()` — Найти точный тестовый узел или Cargo-узел вида имя@версия.

`src/versions.py`:

- `version_key()` — Вернуть сравнимый ключ SemVer, игнорируя метаданные сборки.
- `parse_clause()` — Разобрать один компаратор, сокращенную версию или wildcard.
- `expand_version()` — Дополнить сокращенную версию нулями и проверить SemVer.
- `parse_wildcard()` — Проверить wildcard и вернуть фиксированную часть версии.
- `upper_bound()` — Вычислить исключенную верхнюю границу диапазона.
- `caret_position()` — Найти компонент, ограничивающий совместимость caret.
- `compare_partial()` — Сравнить полную или сокращенную версию с компаратором.
- `matches_clause()` — Проверить один компаратор требования Cargo.
- `prerelease_allowed()` — Разрешить prerelease только для явно указанного ядра версии.
- `matches_requirement()` — Проверить все компараторы Cargo, соединенные запятыми.

`src/visualize.py`:

- `label()` — Получить безопасную подпись узла графа.
- `plantuml_text()` — Описать все вершины и ребра, включая циклы и изолированные узлы.
- `render_svg()` — Передать PlantUML локальному Java-процессу и проверить SVG.
- `save_graph()` — Сохранить описание .puml и SVG по заданному пути.
